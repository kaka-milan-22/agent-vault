## [Unreleased]

### Changed

- **UNVAULTED placeholder fingerprint expanded from 8 to 12 hex chars** (32-bit → 48-bit prefix).

  The previous 8-char (32-bit) prefix made targeted sha256 collisions cheap —
  a few minutes of brute force on a laptop is enough to find an arbitrary
  high-entropy string that hashes to a chosen prefix. This opened an
  **integrity attack on the write path**: an adversary able to plant a
  colliding value in the destination file (e.g. via prompt injection that
  convinces the agent to merge in attacker-controlled content) could cause
  `restoreUnvaulted()` to silently substitute the attacker's value for the
  user's real secret. The user never sees the swap — the placeholder is
  identical before and after.

  A 48-bit prefix (2^48 ≈ 2.8 × 10^14 trials) pushes targeted collision cost
  from "trivial on a laptop" to "infeasible without serious GPU resources,"
  and reduces the chance of accidental collision within a single file to
  effectively zero.

  **Backward compatibility:** placeholders generated by older versions
  (8 hex chars) still resolve correctly. The match regex accepts `{8,16}`
  hex, and `restoreUnvaulted()` compares against the candidate value's full
  sha256 sliced to the placeholder's actual prefix length. No user-facing
  migration required; existing redacted artifacts continue to round-trip.
